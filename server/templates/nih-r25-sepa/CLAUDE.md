# NIH SEPA application (R25, PAR-27-077)

A Typst project for an NIH Science Education Partnership Award: research
education for pre-college students and teachers (`grant.yaml` has the program). It is
edited live by people in tydig while you work, so keep each change small and
focused.

## Where things are

- `grant.yaml`: every fact stated more than once (title, people, effort,
  aims, budget, letters). Change a fact here, never in the `.typ` files.
- `main.typ`: Specific Aims, the Research Education Program Plan (uploaded as
  the Research Strategy) and References in one document, so `@citations`
  resolve. Each part is a `#section(...)`; `make` cuts the PDF at those
  sections, so keep their keys (`aims`, `strategy`, `references`) and their
  order. The Plan's headings are PAR-27-077's required parts, in its order:
  keep them all; the RCR plan is required or the application is not reviewed.
- `#todo[...]` (grey) says what a passage must cover. Replace it with the
  text; never leave one in a finished section.
- `summary.typ`, `narrative.typ`, `budget.typ`, `resources.typ`,
  `humans.typ`, `sharing.typ`, `letters.typ`: one NIH attachment each. There
  is no Data Management and Sharing Plan for this NOFO (`dmsp.typ` can go).
- `letters:` in `grant.yaml` must keep the letter of institutional
  commitment; partners' letters are a page each.
- `lib/nih.typ`: NIH formatting; `lib/grant.typ`: the `section`, `letter`
  and `todo` helpers. `lib/brand.typ`: colours and letterhead.
- `refs.bib`: references; cite them as `@key` in `main.typ` only.
- `package.yaml`: every component of the application, in NIH's order, and
  where each comes from (built here, uploaded into `docs/`, or an online
  form). The Checklist panel and `make full` read it. Add or drop items to
  match the funding opportunity.
- `budget.yaml`: the budget's inputs (salaries, effort, rates, costs). The
  detailed R&R budget, not modules: at most $250,000 direct a year, F&A at
  8%, the PD/PI at least 2.0 person months a year, participant costs
  itemised. `lib/budget.typ` computes every total from it, and warns in red
  where a rule is broken; never type a total into a `.typ` file. `budget-report.typ` is the detailed internal budget.
- `out/`: built PDFs. Generated by `make`; never edit or commit it.

## Rules

- No web addresses in the Plan (they show red). The program website is named,
  not linked.
- Paths start with `/` (`image("/assets/x.svg")`). A relative path resolves
  from the file that contains it, not from the document being compiled.
- Page limits come from `limits:` in `grant.yaml`. A section over its limit
  shows a red warning on its first page: shorten the text, never the
  formatting.
- NIH format: 11 pt Liberation Sans (Arial's metrics), margins of at least
  0.5 in, no headers, footers or page numbers. Do not change these in
  `lib/nih.typ`.
- A letter's `body:` in `grant.yaml` is Typst markup; `#pi`, `#G` and `#todo` are
  available in it.
- Check limits and budget rules against the funding opportunity (`nofo:`),
  which can override the defaults here.

## Building

`make` builds every attachment into `out/`; `make out/strategy.pdf` builds
one; `make full` assembles the whole application into `out/full.pdf`, opened
by a checklist page and marking what is still missing; `make budget` writes
the budget into `out/budget.xlsx` (into the institution's template if
`budget.yaml` maps one). It needs `typst` 0.15 (the build sandbox has it) on PATH.

## Git

If you work in a clone of the project's repository, commit and push as
usual: the hub merges your change into the live text. If you work in the
hub's own folder (`<data folder>/<project>/`), edit files only and never run git
there: that history belongs to the hub.
